# Lessons Learned

## Overview

Developing the **Container Terminal Decision Support System** as the Capstone project for Google's **5-Day AI Agents: Intensive Vibe Coding Course** provided valuable technical, engineering, and project management experience.

Beyond implementing an AI-powered prototype, the project offered practical insights into modern AI application development, software engineering practices, and iterative design.

This document summarises the most important lessons learned throughout the project.

---

# 1. Technical Lessons

## Spec-Driven Development Improves Consistency

Developing the project from a Software Requirements Specification (SRS) significantly reduced ambiguity during implementation.

Having clearly defined requirements made it easier to generate focused AI Studio prompts and maintain consistency across iterations.

---

## Small Prompts Produce Better Results

One of the most important discoveries during the project was that smaller, well-defined AI Studio prompts consistently produced more reliable and predictable results than large, complex prompts.

Breaking development into multiple iterations reduced implementation risk and simplified debugging.

---

## AI Studio is Most Effective for Incremental Development

Rather than generating an entire application in a single step, AI Studio performed significantly better when each iteration introduced only a limited number of new features.

This approach also made validation much easier.

---

## Human-in-the-Loop Adds Significant Value

Introducing Human-in-the-Loop (HITL) transformed the prototype from an automated recommendation system into a human-centred decision support application.

Human review increased transparency, trust, and operational accountability.

---

## Explainability Improves User Trust

Decision Transparency features such as:

- Decision Confidence
- Primary Decision Factors
- Reasoning Summary
- Operational Assumptions

made the recommendations easier to understand and significantly improved user confidence in the generated operational plans.

---

## Documentation Should Evolve with the Software

Maintaining documentation alongside implementation prevented inconsistencies between requirements, architecture, and the final application.

The documentation became an essential part of the development process rather than an afterthought.

---

# 2. Project Management Lessons

## Incremental Development Reduces Risk

Developing the application through five clearly defined iterations made the project easier to manage and significantly reduced implementation risk.

Each iteration had a single objective and could be validated independently.

---

## Frequent Validation Saves Time

Testing every iteration immediately after implementation helped identify issues early and prevented larger problems later in the project.

---

## Version Control is Essential

Regular commits and GitHub updates created a reliable development history and made the project easier to maintain.

Documenting each iteration also improved traceability.

---

## Documentation is Part of the Product

Project documentation should not be considered separate from software development.

The SRS, architecture, roadmap, evaluation, and iteration reports became valuable project artefacts that improved maintainability and communication.

---

# 3. AI Engineering Lessons

Developing an AI application involves much more than generating code.

Important architectural concepts include:

- Skill-Based Architecture
- Human-in-the-Loop
- Decision Transparency
- Responsible AI
- Operational Governance
- Explainability
- Trustworthiness

These concepts contribute directly to user trust and system usability.

---

# 4. Personal Reflections

This project demonstrated that AI-assisted software development is most effective when combined with structured software engineering practices.

Rather than relying on AI to generate an entire application in one step, guiding the development process through clear specifications, incremental iterations, and continuous validation produced a significantly better result.

The project also reinforced the importance of combining technical implementation with documentation, architecture, and thoughtful design.

Perhaps the most valuable lesson was recognising that successful AI systems are not defined solely by intelligent recommendations, but by how clearly they explain their reasoning, support human decision-makers, and build user trust.

---

# Key Takeaways

The most important lessons learned during this project include:

- Define requirements before implementation.
- Keep AI prompts focused and incremental.
- Validate every iteration.
- Maintain documentation throughout development.
- Human oversight increases trust.
- Explainability is essential for decision support.
- Responsible AI principles should be considered from the beginning.
- GitHub documentation is as valuable as the source code.
- Incremental development produces higher quality software.
- Building AI applications requires software engineering discipline as much as AI capability.

---

# Conclusion

The Capstone project successfully demonstrated that combining modern AI Agent concepts with structured software engineering practices results in a more reliable, maintainable, and trustworthy decision support system.

Beyond delivering a working prototype, the project provided valuable experience in AI-assisted development, iterative software engineering, and human-centred AI design.

The lessons learned during this project will serve as a strong foundation for future work involving AI-powered decision support systems, agent engineering, and trustworthy AI applications.
